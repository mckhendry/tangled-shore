# What the reader wants from Spider

This is one reader's example: the profile Spider was first tuned on. Rewrite it for yourself. The judge's prompt
reads this file as written, in priority order.

The reader is an engineer who builds with Claude Code every day. They read each post in about two minutes and want to know what changed in AI since the last post that matters to them. In priority order:

1. **Models and labs:** new models, major version releases, pricing and availability changes, and policy moves
   that change what the reader can use.
2. **Dev tools:** Claude Code first, then other coding agents, IDEs, SDKs and MCP. Release notes count when they
   change how the reader works; a patch release of bug fixes does not.
3. **Research papers:** only breakouts, meaning a paper the labs, Hacker News or the Hugging Face list are talking
   about, not new arXiv volume.
4. **Funding and business:** only big moves, such as raises over $1B, acquisitions, or exec departures at the
   major labs.
5. **New videos:** from the creators in `creators.json`, one line each, folded into the same post.

Two rules:

- Popularity is evidence, not importance.
- Announced is not shipped, so each item says which it is.
